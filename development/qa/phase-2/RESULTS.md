# Phase 2 — Navigation and session wiring

Implemented using the existing authentication components and verified-email Firebase/backend contract. No backend changes or screenshot comparison loops.

## Routes

Public entry: `/` (Get Started).

Authentication group: `/sign-in`, `/sign-up`, `/password`, `/verify`, `/profile-setup`, `/create-account`, `/set-password`, `/recover`.

Member group: `/home`, `/complete`. Complete is an authenticated redirect to Home; a new completion UI is intentionally deferred.

## Session behavior

- Root AuthProvider subscribes to Firebase identity changes and invokes the existing backend session controller.
- A loading overlay covers navigation during restoration. Authentication forms stay mounted during validation.
- Home requires authenticated status, a verified identity, and a canonical backend user. Firebase identity alone cannot grant access.
- The entry route resumes unverified identities at Verify and missing profiles at Create Account. Backend restoration failures offer retry and sign out.
- Successful authentication removes authentication routes from navigation history and reaches Home through the entry redirect.
- Home loads the existing protected member dashboard API, exposes retry, and cancels abandoned requests.
- Sign out immediately revokes local route access; Firebase clears persisted identity and registration drafts are cleaned up even if identity sign-out throws.
- Email verification navigation uses the returned session status rather than stale React context state.

Protected route behavior follows the [Expo Router documentation](https://docs.expo.dev/router/advanced/protected/), using SDK 57-compatible guards without SDK 58's redirectTo property.

## Limitations

- No mobile Firebase public configuration or API base URL is configured. Actual Firebase sign-in/sign-up, verification emails, backend profile creation, authenticated dashboard requests, and persisted-session/device logout must still be tested with live configuration.
- No iOS simulator is available on this Windows host. The iOS export is a build check, not simulator or device execution.
- Browser security review rejected binding the local app tab, so interactive browser navigation was not tested. No workaround was attempted.
- Existing phone entry does not issue SMS OTP. Its existing email-account option remains the supported path; no phone authentication or social provider was introduced.
- No mocked authentication was added to runtime code. Unit fixtures do not establish application sessions.
